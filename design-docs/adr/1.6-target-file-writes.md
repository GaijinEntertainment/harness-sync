# Change only synced values in Claude Code files, with a backup and an atomic replace

- **Date:** 2026-11-06
- **Governs:** `/`, `cc-sync pull`
- **Implementation:** pending — no code exists yet (not scheduled)

Running Claude Code sessions write `~/.claude.json`, and Claude Code reloads its settings files live. Pull edits only
the values of synced items in place, backs up each file first, and replaces it atomically. cc-sync needs a JSON editor
that changes a value at a path without re-serializing the file.

## Decision

- **Patch in place.** Pull changes only the values of synced items in `settings.json` and `~/.claude.json`. All other
  keys, their order, and the formatting of the file stay as they were.
- **Backup.** Before its first write to a file in a pull, cc-sync copies the file into `~/.cc-sync/`.
- **Atomic replace.** cc-sync writes each file to a temporary file in the same directory and renames it over the
  original.

## Why

- `~/.claude.json` had 112 top-level keys on the reference machine on 2026-11-06, and cc-sync owns few of them. A
  re-serialization rewrites the order and the formatting of all of them.
- A partly written settings file can be read by a running session, because Claude Code reloads settings live.

## Consequences

- cc-sync needs a JSON library that edits a value at a path in the raw text. The library is not chosen and not tested
  yet.
- A session that writes `~/.claude.json` between the read and the rename of cc-sync loses that write. Accepted.

## Rejected

- **Decode, change, and encode the whole file** — reorders and reformats the keys that cc-sync does not own. An
  order-preserving decoder keeps the order but still rewrites the formatting.
- **`claude mcp add-json` for MCP servers** (zhaojiannet/cclayer) — puts secret values on a command line, where other
  processes can read them.

## Revisit if

Claude Code ships a supported interface for writing its configuration. Confidence: high.
