# Change only synced values in harness files, with a backup and an atomic replace

- **Date:** 2026-11-06
- **Governs:** `/`, `harness-sync pull`, `harness-sync secret set`

Running harness sessions write their own files, such as Claude Code's `~/.claude.json`, and Claude Code reloads its
settings files live. Pull edits only the values of synced items in place, backs up each file first, and replaces it
atomically. harness-sync needs a JSON editor that changes a value at a path without re-serializing the file.

## Decision

- **Patch in place.** Pull changes only the values of synced items in a keyed JSON file. All other keys, their order,
  and the formatting of the file stay as they were.
- **Backup.** Before its first write to a file in a pull, harness-sync copies the file into `~/.harness-sync/backups/`.
- **Atomic replace.** harness-sync writes each file to a temporary file in the same directory and renames it over the
  original, with the permissions of the original.

## Why

- `~/.claude.json` had 112 top-level keys on the reference machine on 2026-11-06, and harness-sync owns few of them. A
  re-serialization rewrites the order and the formatting of all of them.
- A partly written settings file can be read by a running session, because Claude Code reloads settings live.

## Consequences

- Pull edits the raw text through the CST of `jsonc-parser`. A value that pull adds takes the formatting of the library,
  not the formatting of the file: an added array is written on one line. Accepted.
- A session that writes a file between the read and the rename of harness-sync loses that write. Accepted.

## Rejected

- **Decode, change, and encode the whole file** — reorders and reformats the keys that harness-sync does not own. An
  order-preserving decoder keeps the order but still rewrites the formatting.
- **The CLI of the harness for MCP servers** (`claude mcp add-json`, `pi mcp add`; zhaojiannet/cclayer) — puts secret
  values on a command line, where other processes can read them.

## Revisit if

A harness ships a supported interface for writing its configuration. Confidence: high.
