# Sync the plugin declarations and let each harness install the plugins

- **Date:** 2026-11-06
- **Governs:** `/`, `harness-sync status`, `harness-sync push`, `harness-sync pull`

Claude Code and pi keep their plugin setup in two layers: declarations in settings, and installed copies on disk.
harness-sync syncs only the declarations and runs no harness command. Each harness installs what its declarations name
after its next start.

## Decision

- **Declarations.** Claude Code: the `enabledPlugins`, `extraKnownMarketplaces`, and `pluginConfigs` entries of
  `settings.json`; a marketplace syncs only as its `extraKnownMarketplaces` entry, with its source and `autoUpdate`. pi:
  the `packages`, `extensions`, `skills`, `prompts`, and `themes` keys of `settings.json`.
- **No install records.** harness-sync never syncs installed copies or install records: Claude Code
  `installed_plugins.json`, `known_marketplaces.json`, and `plugins/cache/`; pi `npm/` and its cloned git packages.
- **The harness installs.** Pull writes the declarations as it writes any setting, and runs no harness command. Pull
  never removes an installed copy.
- **Undeclared Claude Code marketplaces.** Status and push warn about each marketplace that `known_marketplaces.json`
  records and settings do not declare, and show the declaration to add.

## Why

- Claude Code install records hold absolute install paths, one record per project, and no source (research,
  2026-11-04). After a session starts, Claude Code clones a declared marketplace that it lacks and downloads the enabled
  plugins that are not cached (Claude Code plugin docs, `plugins/loading.md`).
- `claude plugin marketplace add` declares each marketplace that it adds in user settings (probe with Claude Code
  2.1.319, 2026-11-06), so a marketplace added from the CLI reaches the declarations.
- pi installs declared npm and git packages into its own directories, and `pi update --extensions` reconciles them (pi
  `docs/packages.md`, 2026-11-07).
- The user: let the harness handle the install, and do not work around the behavior of its CLI.

## Consequences

- A Claude Code marketplace that settings do not declare does not sync until the user declares it. On the reference
  machine, 4 of 7 marketplaces were not declared (2026-11-07). Accepted.
- Plugins arrive after the next start of the harness. Accepted.
- A declaration removed on one machine leaves the installed copy on the other machines. Accepted.
- A pi package declared by a local path needs its directory on every machine; the repo's `include` list adds it.
  Accepted.
- A declaration without a ref takes the current head of its source, so versions can differ between machines. Accepted.

## Rejected

- **Copying the install records and the cache** (FelixIsaac/claude-code-sync) — moves the absolute paths and the
  per-project records of another machine.
- **`claude plugin marketplace add` and `remove` in pull** — `add` drops `autoUpdate`, a `claude` run on a new machine
  rewrote other settings, pull needed `claude` on PATH, and `remove` uninstalls the plugins of the marketplace (probes
  with Claude Code 2.1.319, 2026-11-06 and 2026-11-07).
- **Marketplace items from `known_marketplaces.json`** — the record stays on a machine after its declaration goes, so a
  removal on one machine reads as an addition on the next.
- **`claude plugin install` or `pi install` for each plugin** — does what the harness does itself after a start.

## Revisit if

A harness does not install a declared plugin after its next start. Confidence: medium. The docs state the behavior, and
no probe has seen it with a logged-in harness.
