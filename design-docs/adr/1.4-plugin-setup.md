# Sync the plugin declarations and let Claude Code install the plugins

- **Date:** 2026-11-06
- **Governs:** `/`, `cc-sync pull`

Claude Code keeps the plugin setup in two layers: declarations in settings, and install records with a cache on disk.
cc-sync syncs only the declarations and runs no Claude Code command. Claude Code clones the declared marketplaces and
downloads the enabled plugins after its next session starts.

## Decision

- **Declarations.** The plugin setup items are the `enabledPlugins`, `extraKnownMarketplaces`, and `pluginConfigs`
  entries of `settings.json`. A marketplace syncs only as its `extraKnownMarketplaces` entry, with its source and
  `autoUpdate`.
- **No install records.** cc-sync never syncs `installed_plugins.json`, `known_marketplaces.json`, or `plugins/cache/`.
- **Claude Code installs.** Pull writes the declarations as it writes any setting, and runs no `claude` command. Claude
  Code clones a declared marketplace that it lacks and downloads the enabled plugins that are not in its cache. Pull
  never removes a marketplace clone and never uninstalls a plugin.
- **Undeclared marketplaces.** Status and push warn about each marketplace that `known_marketplaces.json` records and
  settings do not declare, and show the declaration to add.

## Why

- Install records hold absolute `installPath` values, one record per project path, and no source (research, 2026-11-04).
- After a session starts, Claude Code clones a marketplace that settings declare and `known_marketplaces.json` lacks,
  then downloads the enabled plugins that are not cached. It fetches a plugin that user settings enable, also from an
  external source (Claude Code plugin docs, `plugins/loading.md`).
- `claude plugin marketplace add` declares each marketplace that it adds in user settings (probe with Claude Code
  2.1.319, 2026-11-06), so a marketplace added from the CLI reaches the declarations without a step from the user.
- The user: let Claude Code handle the install when it starts, and do not work around the behavior of its CLI.

## Consequences

- A marketplace that `known_marketplaces.json` records and settings do not declare does not sync until the user
  declares it. On the reference machine, 4 of 7 marketplaces were not declared (2026-11-07). Accepted.
- Plugins arrive after the background fetch of the next Claude Code session, and become active in the session after
  that or after `/reload-plugins`. Accepted.
- A declaration removed on one machine leaves the clone and its plugins on the other machines, where the user removes
  them. Accepted.
- `known_marketplaces.json` has no ref, so each machine takes the current marketplace head. Plugin versions can differ
  between machines. Accepted.

## Rejected

- **Copying the install records and the cache** (FelixIsaac/claude-code-sync) — moves the absolute paths and the
  per-project records of another machine.
- **`claude plugin marketplace add` and `remove` in pull** — `add` rewrites the declaration as its source alone and
  drops `autoUpdate`, a `claude` run on a new machine rewrote other settings, pull needed `claude` on PATH, and `remove`
  uninstalls the plugins of the marketplace (probes with Claude Code 2.1.319, 2026-11-06 and 2026-11-07).
- **Marketplace items from `known_marketplaces.json`** — the record stays on a machine after its declaration goes, so a
  removal on one machine reads as an addition on the next.
- **`claude plugin install` for each plugin** (LandB/claudesync, GiuseppeBellamacina/claude-code-sync) — does what
  Claude Code does after startup for enabled plugins.

## Revisit if

A logged-in Claude Code on a new machine does not clone a declared marketplace or download its enabled plugins after the
session starts. Confidence: medium. The docs state the behavior, and no probe has seen it, because a sandbox home is not
logged in.

## History

- 2026-11-07 — Undeclared marketplaces: status and push warn about them, because they stopped syncing when pull
  moved to declarations alone.
- 2026-11-07 — Claude Code installs: pull writes marketplace declarations and runs no `claude` command, because the CLI
  changed settings behind cc-sync and Claude Code clones a declared marketplace itself.
- 2026-11-07 — Install through Claude Code: pull sets `autoUpdate` on the declaration that the CLI writes, because the
  CLI drops it and the declaration's value is the one Claude Code uses.
- 2026-11-06 — Install through Claude Code: pull skips the CLI for a marketplace that settings declare, because the CLI
  records an added marketplace in settings and a CLI removal uninstalls its plugins.
