# Sync the plugin declarations and let Claude Code install the plugins

- **Date:** 2026-11-06
- **Governs:** `/`, `cc-sync pull`

Claude Code keeps the plugin setup in two layers: declarations in settings, and install records with a cache on disk.
cc-sync syncs the declarations and the marketplace sources, and lets Claude Code clone and download. A plugin becomes
active only at the next start of Claude Code.

## Decision

- **Declarations.** The plugin setup items are `enabledPlugins`, `extraKnownMarketplaces`, and `pluginConfigs` from
  `settings.json`, and one marketplace item per marketplace that `known_marketplaces.json` records or
  `extraKnownMarketplaces` declares, with its source and `autoUpdate`. Where both set a field, the declaration's value
  wins, as in Claude Code. The install locations in `known_marketplaces.json` are not items.
- **No install records.** cc-sync never syncs `installed_plugins.json`, `known_marketplaces.json` as a file, or
  `plugins/cache/`.
- **Install through Claude Code.** Pull adds a marketplace with `claude plugin marketplace add <source>` and removes one
  with `claude plugin marketplace remove <name>`, except a marketplace that `extraKnownMarketplaces` declares after the
  pull: Claude Code clones that one at its next start, and pull never removes it. After an add, pull sets the remote
  `autoUpdate` on the declaration that the CLI wrote. Claude Code downloads the enabled plugins that are not in its
  cache when it starts.
- **Incomplete plugin setup.** When a `claude` call fails or `claude` is not on PATH, pull exits with an error and does
  not move the base commit, so a later push cannot send the missing marketplace as a deletion.

## Why

- Install records hold absolute `installPath` values, one record per project path, and no source (research, 2026-11-04).
- On the reference machine, 3 of 5 marketplaces were only in `known_marketplaces.json` (2026-11-04). The settings keys
  alone lose them.
- Claude Code clones the marketplaces that user settings declare and downloads enabled plugins at startup (Claude Code
  plugin docs).
- `claude plugin marketplace add` runs without a TTY and records the marketplace both in `extraKnownMarketplaces` of
  user settings and in `known_marketplaces.json` (probe with Claude Code 2.1.319 and a sandbox `CLAUDE_CONFIG_DIR`,
  2026-11-06). A removal through the CLI uninstalls the plugins of the marketplace, so a marketplace that moved into
  settings must never read as removed.
- Claude Code takes the `autoUpdate` of a marketplace from its `extraKnownMarketplaces` entry first, and from
  `known_marketplaces.json` only when the entry does not set it (Claude Code plugin docs). `claude plugin marketplace
  add` rewrites the declaration as its source alone and drops `autoUpdate` (probe with Claude Code 2.1.319,
  2026-11-07).

## Consequences

- Pull needs the `claude` CLI on PATH for a marketplace that settings do not declare. A pull without it stops before
  the base commit moves, so push stays blocked until a pull completes. Accepted.
- Plugins become active at the next start of Claude Code or after `/reload-plugins`. Accepted.
- `known_marketplaces.json` has no ref, so each machine takes the current marketplace head. Plugin versions can differ
  between machines. Accepted.

## Rejected

- **Copying the install records and the cache** (FelixIsaac/claude-code-sync) — moves the absolute paths and the
  per-project records of another machine.
- **Settings keys only** (Hudint/claudesync) — loses the marketplaces added with `claude plugin marketplace add`.
- **`claude plugin install` for each plugin** (LandB/claudesync, GiuseppeBellamacina/claude-code-sync) — does what
  Claude Code does at startup for enabled plugins.

## Revisit if

A probe shows that Claude Code does not download enabled plugins from a marketplace that the CLI added, or Claude Code
changes its startup install. Confidence: medium, because the startup download is not verified on a new machine.

## History

- 2026-11-07 — Install through Claude Code: pull sets `autoUpdate` on the declaration that the CLI writes, because the
  CLI drops it and the declaration's value is the one Claude Code uses.
- 2026-11-06 — Install through Claude Code: pull skips the CLI for a marketplace that settings declare, because the CLI
  records an added marketplace in settings and a CLI removal uninstalls its plugins.
