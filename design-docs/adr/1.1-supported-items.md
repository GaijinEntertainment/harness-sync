# Sync only the items in the catalog, one JSON key at a time

- **Date:** 2026-11-06
- **Governs:** `/`, `cc-sync status`, `cc-sync push`, `cc-sync pull`
- **Implementation:** pending — the referenced files and the `include` and `exclude` lists are not built (frame Phase 3)

`~/.claude/` and `~/.claude.json` mix the user-level setup with state, caches, and identity that Claude Code writes for
itself. cc-sync moves only the supported items in a catalog, and splits JSON files into one item per key. New Claude
Code configuration does not sync until the catalog names it.

## Decision

- **Catalog.** cc-sync reads, compares, and writes only the supported items in the catalog. It never puts another file
  or key from `~/.claude/` or `~/.claude.json` into the remote snapshot, and pull never writes one.
- **Key-level JSON.** Each top-level key of `~/.claude/settings.json` is one item. A map of independent entries is one
  item per entry: `env`, `enabledPlugins`, `extraKnownMarketplaces`, `pluginConfigs`, `skillOverrides`, `modelSettings`,
  and `mcpServers`.
- **`~/.claude.json` keys.** The items from `~/.claude.json` are: the top-level `mcpServers`; the keys that the settings
  reference lists with the "Global config" scope; the settings keys that the settings reference says fall back to
  `~/.claude.json`; and the undocumented preference keys `autoUpdates`, `showSpinnerTree`, `diffSidebarOpen`,
  `deepLinkTerminal`, `lspRecommendationDisabled`, and `companionMuted`. No key under `projects` is an item.
- **Files.** Each file of the user instructions (`CLAUDE.md`, `rules/`), `skills/` except `skills/synced/`, `agents/`,
  `commands/`, `output-styles/`, `workflows/`, `themes/`, and `keybindings.json` is one item.
- **Referenced files.** A file under `~/.claude/` that a synced item points to is an item: a path in a synced JSON
  string value, or an `@` import or a relative link in a synced Markdown file. cc-sync does not parse scripts for
  references.
- **Include and exclude.** The repo holds an `include` list that adds files and key paths to the catalog, and an
  `exclude` list that removes items, referenced files included. Both apply on every machine.
- **Out of the catalog.** Memory, `agent-memory/`, claude-mem data, `pluginPanes`, `companion`, credentials, plugin
  install records and the plugin cache, the `synced/` directories, and all other state that Claude Code writes are not
  built-in items. `include` cannot add a credentials file.
- **Claude Code paths.** When `CLAUDE_CONFIG_DIR` is set, cc-sync reads the Claude Code files from that directory, as
  Claude Code does.

## Why

- `~/.claude.json` had 112 top-level keys on the reference machine on 2026-11-06, and 11 of them were configuration. The
  others were counters, caches, flags, identity, and per-project state.
- On the reference machine, `settings.json` held a secret in `env` and an absolute home path in `statusLine.command`
  next to portable keys (2026-11-04). Key-level items let cc-sync mask or pin these values and move the rest.
- A denylist over `~/.claude/` leaks each new state file that a Claude Code release adds. A catalog only misses new
  configuration, which is the safe failure.
- User instructions and settings point to files (`guides/` from `CLAUDE.md`, `statusline.mts` from `statusLine`).
  Without referenced files, a setting syncs and the file it needs does not.

## Consequences

- New Claude Code configuration does not sync until the built-in list or the repo's `include` list names it. How the
  list of undocumented keys stays current is not specified. Accepted.
- cc-sync syncs six undocumented keys on a guess about their meaning. If one of them is state, cc-sync syncs state.
  Accepted.
- A file that only a script points to is not a referenced file. The repo's `include` list covers it. Accepted.

## Rejected

- **Whole-directory sync with a denylist** (renefichtmueller/claude-sync, perfectra1n/claude-code-sync) — `~/.claude/`
  holds more than 20 kinds of state that Claude Code writes, and each release can add more.
- **Whole-file sync of `settings.json`** — puts the secret and the home path into the snapshot, and makes every edit of
  the file on two machines one conflict.
- **Only `mcpServers` from `~/.claude.json`** (tawanorg/claude-sync, aoprisan/ccsync) — misses the Global config keys
  and the fallback keys that `/config` still writes there.
- **Whole-file encryption of `~/.claude.json`** (FelixIsaac/claude-code-sync) — moves the identity, `machineID`, and
  per-project state of one machine onto another.

## Revisit if

Claude Code documents a split of configuration and state in `~/.claude.json`, or ships a native sync of the user-level
setup. Confidence: medium. Version 2.1.119 moved `/config` preferences to `settings.json`, and the move can continue.
