# Sync each harness on its own, through its catalog of supported items

- **Date:** 2026-11-06
- **Governs:** `/`, `harness-sync status`, `harness-sync push`, `harness-sync pull`
- **Implementation:** pending — the code knows one harness, Claude Code, and has no harness abstraction (not scheduled)

Every harness keeps its user-level setup in its own directory, mixed with state, caches, and credentials that it writes
for itself. harness-sync moves only the supported items in the catalog of each harness, splits keyed JSON files into
one item per key, and never converts a value from one harness to another. New configuration of a harness does not sync
until its catalog names it.

## Decision

- **Catalog per harness.** Each harness has a catalog of keyed JSON files, whole files, and directories of whole files.
  harness-sync reads, compares, and writes only the supported items of the catalogs. It never puts another file or key
  into the remote snapshot, and pull never writes one.
- **Each harness on its own.** An item belongs to one harness, or to no harness as a root file. harness-sync never moves
  or converts a value from one harness to another.
- **Key-level JSON.** Each top-level key that the catalog admits from a keyed JSON file is one item. A key that holds a
  map of independent entries is one item per entry. The catalog of each harness names these keys
  ([1.12](/design-docs/adr/1.12-claude-code-catalog.md), [1.13](/design-docs/adr/1.13-pi-catalog.md)).
- **Files.** Each whole file of a catalog, and each file in a catalog directory, is one item. `node_modules`
  directories and `.DS_Store` files never sync.
- **Referenced files.** A file under a harness directory that a synced item points to is an item: a path in a synced
  JSON string value, or an `@` import or a relative link in a synced Markdown file. harness-sync does not parse scripts
  for references.
- **Include and exclude.** The repo's `include` list adds files, directories, and keys to the catalog, including root
  files that no harness owns. Its `exclude` list removes items, referenced files included. Both apply on every machine.
- **Never synced.** Credentials, sessions, caches, install records, and other state that a harness writes are not items.
  Each harness lists its own, and `include` cannot add a credentials file.

## Why

- The brief: each harness syncs on its own, and a value of one harness never becomes a value of another. The user:
  "interop is impossible, hence the difference".
- `~/.claude.json` had 112 top-level keys on the reference machine, and 11 of them were configuration (2026-11-06). pi's
  agent directory holds sessions, an npm tree, caches, and credentials next to its settings (2026-11-07).
- A denylist over a harness directory leaks each new state file that a harness release adds. A catalog only misses new
  configuration, which is the safe failure.
- Settings and instructions point to files, such as a status line script or a linked guide. Without referenced files,
  a setting syncs and the file it needs does not.

## Consequences

- New configuration of a harness does not sync until its catalog or the repo's `include` list names it. Accepted.
- A file that only a script points to is not a referenced file; `include` covers it. Accepted.
- A directory that two harnesses read, such as `~/.agents/skills/`, syncs only as root files that `include` adds.
  Accepted.

## Rejected

- **Whole-directory sync with a denylist** (renefichtmueller/claude-sync, perfectra1n/claude-code-sync) — a harness
  directory holds more than 20 kinds of state, and each release can add more.
- **Whole-file sync of a settings file** — puts secrets and home paths into the snapshot, and makes every edit of the
  file on two machines one conflict.
- **One source converted into the format of each harness** (spxrogers/agentsync, rulesync, ruler) — the harnesses differ
  in keys and features, the converters report lossy cases, and the brief makes interop a non-goal.

## Revisit if

A harness ships a documented split of configuration and state, or a native sync of its user-level setup. Confidence:
medium.
