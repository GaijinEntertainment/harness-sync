# Pull from one primary target and push to the other targets on request

- **Date:** 2026-11-07
- **Governs:** `/`, `cc-sync init`, `cc-sync target`, `cc-sync push`
- **Implementation:** pending — `push --to`, and the push to a target that is not the primary (not scheduled)

One user keeps the setup in more than one git repo, such as a personal GitHub repo and a company Gerrit repo. Each
machine names the repos it uses as targets and picks one primary target. Status, pull, and the base commit use only the
primary, so the three-way comparison stays as it is; a push to another target replaces that target's snapshot.

## Decision

- **Targets per machine.** The sync configuration holds each target with its name, URL, and branch, and the name of the
  primary target. `init` creates the first target as the primary.
- **One primary.** Status, pull, the conflict check, and the base commit use the primary target alone
  ([1.3](/design-docs/adr/1.3-concurrent-changes.md)). `push` without `--to` sends to the primary.
- **Switching drops the base.** Making another target primary deletes the base commit, so the first pull from it treats
  each item that differs as a conflict.
- **Push to other targets.** `push --to <name>`, or `--to all`, also sends to targets that are not the primary. Their
  snapshot becomes this machine's setup, as a new commit on their branch, without a conflict check.
- **A target's own settings.** A push to a target applies the `secrets`, `include`, and `exclude` of that target's
  `cc-sync.toml`, so a target can hold a subset of the setup.

## Why

- The user: one main repo, other repos to push to when needed, and the choice of repos and of the primary per machine,
  because each machine knows where it can pull from and push to. Each repo carries the settings of its own storage.
- Without dropping the base, the values of a primary with older content read as remote changes, and pull applies them
  without a conflict (end-to-end test, 2026-11-07).

## Consequences

- Two machines that push to the same target that is not their primary overwrite each other there. Accepted.
- A change made in a target that is not the primary reaches this machine only after it becomes the primary. Accepted.

## Rejected

- **Targets in the repo's `cc-sync.toml`** — the repos that a machine can reach, and its primary, differ per machine.
- **A three-way comparison with every target** — each target would need its own base commit, and pull would have to
  settle conflicts between targets.

## Revisit if

A machine needs to take changes from more than one target. Confidence: high.
