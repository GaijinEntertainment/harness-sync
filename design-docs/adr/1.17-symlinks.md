# Never follow a symlink below the home directory

- **Date:** 2026-11-08
- **Governs:** `/`, `harness-sync status`, `harness-sync push`, `harness-sync pull`, `harness-sync secret set`
- **Pinned by:** `crates/harness-sync/tests/e2e/files.rs` (`push_skips_a_file_behind_a_symlink`,
  `pull_never_writes_through_a_symlink`)

Dotfiles managers such as GNU Stow link the files and directories of a harness into the home directory. harness-sync
never reads or writes through a symlink below the home directory, so a linked file stays with the tool that linked it,
and a linked directory does not sync.

## Decision

- **No symlink in the path.** A file syncs only when no part of its local path below the home directory is a symlink.
  Where an environment variable moves a harness root, the check starts below the directory that the variable names, and
  that directory can be a symlink.
- **Not synced on this machine.** This machine leaves a file behind a symlink out of its local setup and out of its
  view of the remote snapshot and the base commit. Status does not list it, pull does not write it, and push keeps it
  in the remote snapshot. A keyed JSON file behind a symlink is skipped as a whole, and `secret set` refuses to write
  it.

## Why

- The user: "never follow symlinks" (2026-11-08).
- A write through a symlinked directory lands outside the harness directory, and the atomic replace of
  [1.6](/design-docs/adr/1.6-target-file-writes.md) swaps a symlinked file for a regular file, which cuts the link that
  the dotfiles manager keeps.
- A reference through a symlinked directory can name a file outside the home directory.

## Consequences

- A linked harness directory, such as a `~/.claude/skills/` that GNU Stow links, does not sync on that machine. When
  `~/.claude` itself is a symlink, no item under it syncs. Accepted.
- harness-sync reports nothing about a file that it skips for a symlink. Accepted.

## Rejected

- **Follow every symlink** — writes leave the home directory, and the atomic replace cuts the link.
- **Follow a symlink whose target lies in the home directory** — the atomic replace still cuts the link of a linked
  file, and two paths then name one file.

## Revisit if

Users need harness-sync on setups that a dotfiles manager links. Confidence: medium.
