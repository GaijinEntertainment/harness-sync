# Send the snapshot to a Gerrit target as a change for review, and never merge it

- **Date:** 2026-11-07
- **Governs:** `/`, `cc-sync init`, `cc-sync target add`, `cc-sync push`

A Gerrit project usually refuses a direct push to a branch and takes a change for review instead. cc-sync sends the
snapshot of a Gerrit target as such a change and leaves the merge to the user. The branch of the target, and the base
commit of a Gerrit primary, move only after the change merges.

## Decision

- **Gerrit kind.** A target added with `--gerrit` receives each push as `<commit>:refs/for/<branch>`.
- **Change-Id.** cc-sync writes a `Change-Id` line into the message of each commit that it sends to a Gerrit target.
  Each push opens a new change.
- **No merge.** cc-sync never approves or submits a change.
- **The base waits for the merge.** A push to a Gerrit primary leaves the base commit as it is. The first pull after the
  merge moves it.
- **Report.** The push report gives the pushed commit and the change URL that Gerrit prints.

## Why

- The user: the company Gerrit takes changes, not direct pushes, and merging a change stays with the user.
- cc-sync compares item values, not commit ids ([1.3](/design-docs/adr/1.3-concurrent-changes.md)). A commit that Gerrit
  rebases or cherry-picks on merge still holds the pushed values, so the pull after the merge finds nothing to change.
- `git push --quiet` keeps the `remote:` lines in which Gerrit prints the change URL (probe, 2026-11-07).

## Consequences

- A change that a later push replaces stays open until the user abandons it. Accepted.
- Until the change merges, status on a machine with a Gerrit primary lists the pushed items as local changes. Accepted.
- A Gerrit project can refuse a commit whose committer email is not an email of the user's account; the committer comes
  from the git configuration of the machine. No push has run against the company Gerrit yet.

## Rejected

- **Push with `%submit`** — the user merges each change; cc-sync automates no review step.
- **Direct push to `refs/heads/<branch>`** — the company Gerrit refuses it.
- **One Change-Id per target until the change merges** — needs machine state per target and handling of abandoned
  changes, while the user merges each change soon after the push.

## Revisit if

Open changes that later pushes replaced pile up in Gerrit. Confidence: medium.
