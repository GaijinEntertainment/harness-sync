# Keep the local value of an item that leaves the sync, warn about it, and remove it only on request

- **Date:** 2026-11-19
- **Governs:** `/`, `harness-sync status`, `harness-sync pull`, `harness-sync retired`
- **Pinned by:** `crates/harness-sync/tests/e2e/retired.rs`
  (`pull_lists_and_warns_about_the_items_that_an_exclude_entry_retired`,
  `the_machine_that_added_the_exclude_entry_has_no_retired_item`,
  `an_excluded_item_that_never_synced_to_this_machine_is_not_retired`)

An `exclude` entry stops the sync of an item and leaves the value that each machine holds. A machine that got the value
through the sync then keeps a value that nothing maintains. harness-sync records such items as retired items, warns
about them, and deletes them only when the operator asks. The machine keeps one more state file.

## Decision

- **Retired item.** An item is retired on a machine when it synced at the base commit of that machine, the `exclude`
  list of the remote snapshot covers it now, and the machine still holds it. An excluded item that never synced to the
  machine is not retired.
- **Record.** The pull that moves the base commit past the `exclude` entry records the retired items in
  `~/.harness-sync/retired-items.toml`, before it moves the base commit. Status records none. An item leaves the
  record when the machine no longer holds it or the `exclude` list no longer covers it. The file exists only while the
  record holds an item: `retired remove` and `retired keep` delete it.
- **Warning.** Status and pull list the retired items in the report. In text output they print a warning that names
  `retired remove` and `retired keep`.
- **Remove on request.** `retired remove` deletes the retired items from the local setup through the writes of
  [1.6](/design-docs/adr/1.6-target-file-writes.md), with a backup. `retired keep` clears the record and leaves the
  values. No other command deletes a retired item.
- **The machine that excludes.** `declarations add exclude` moves the base commit of its machine when that base commit
  is the latest commit of the target and the target publishes the new commit at once. That machine then has no retired
  item and keeps its values without a warning.

## Why

- The user: "suggection for the sync that stops maintaining something - warn the user and suggest the cleaup of those"
  (2026-11-19).
- An `exclude` of a directory marketplace left its three settings entries on a second machine, where they named a
  directory that the machine did not have, and no command showed them (2026-11-19).
- `exclude` also keeps machine-local values out of the sync, such as a marketplace in a local directory. Those values
  are wanted on their machine, so a rule that lists every excluded local value warns about them on every run.
- The base commit tells the two cases apart with no new input: it holds the item only on a machine that got it through
  the sync.

## Consequences

- The record is machine-local state. When it is lost, the retired items that a pull already recorded get no warning.
  Accepted.
- `retired remove` deletes every retired item; it cannot remove one and keep another. Accepted.
- The machine that added the `exclude` entry gets the warning on its next pull when its base commit did not move with
  the entry: the entry came from a hand edit of `harness-sync.toml`, the machine was behind the target, or the target is
  a Gerrit project, whose base commit moves only after the change merges
  ([1.11](/design-docs/adr/1.11-gerrit-targets.md)). `retired keep` settles it. Accepted.
- A machine that stops syncing a harness drops the retired items of that harness from the record. Accepted.
- Status shows no retired item before the pull that meets the `exclude` entry. Accepted.

## Rejected

- **Delete the local value when the item leaves the sync** — a machine can depend on a value that another machine
  excluded, and pull would delete it with no request.
- **Warn about every excluded item that the machine holds** — the values that `exclude` keeps local on purpose would
  warn on every status.
- **Warn only in the pull that sees the change** — the cleanup then has to run in that same command, and a later
  status shows nothing.

## Revisit if

Users need to remove some retired items and keep others. Confidence: medium.
