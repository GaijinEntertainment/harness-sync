# Mirror the home directory in the repo, and name each item by its path

- **Date:** 2026-11-07
- **Governs:** `/`, `harness-sync status`, `harness-sync push`, `harness-sync pull`, `harness-sync declarations`,
  `harness-sync pin`

The repo holds the setup of several harnesses and of files that no harness owns. Each file sits in the repo at its
path relative to the home directory, and each item is named by that path. A reader finds each file where the harness
keeps it, and ids grow longer than the old short forms.

## Decision

- **Home mirror.** Each file of the remote snapshot sits at the default path of its local file relative to the home
  directory: `.claude/settings.json`, `.claude.json`, `.claude/rules/rust.md`, `.pi/agent/models.json`. A harness
  directory that an environment variable moves keeps its default path in the repo.
- **Keyed files.** A keyed JSON file in the repo holds only its synced items, with secret placeholders and home-path
  tokens in place. A whole file holds its content unchanged.
- **Item id.** An item id is the home-relative path with forward slashes. A key item adds `:` and a JSON pointer:
  `.claude/settings.json:/env/EDITOR`, `.claude.json:/mcpServers/context7`. `harness-sync.toml`, pins, conflict
  flags, and reports all use this id.
- **Ownership.** A path belongs to the harness whose directories contain it. A path that no harness owns is a root
  file. Only the repo's `include` list adds root files, and they sync on every machine.
- **Repo settings.** `harness-sync.toml` sits at the repo root and is not a home file.

## Why

- The user: the sync repo has "the root setup + per-harness folders, like `.claude`, `.kensai`, `.pi`", and "root files
  expected to be tracked from the home folder".
- A colleague's hand-maintained sync repo keeps one folder per harness, named after its directory (2026-11-07).
- An id formed from the path needs no second table that maps ids to repo paths, and one id names an item in every
  command and file.

## Consequences

- A sync repo in the earlier layout must be written again in this layout. No migration code exists, because nothing is
  released. Accepted.
- A root file that only one harness reads, such as `~/.agents/skills/`, also syncs to machines without that harness.
  Accepted.

## Rejected

- **Ids prefixed with a harness and a file name** (`claude-code:settings:/model`) — need a source name for each file
  and a second mapping from ids to repo paths.
- **`#` before the JSON pointer** — `#` is a glob operator in zsh with `extendedglob`, and operators type ids in a
  shell.
- **Repo paths from the directory a machine uses** — two machines with different `CLAUDE_CONFIG_DIR` values would write
  one file to two paths.
- **A root other than the home directory** — no case needs one yet. The user: "these must be solved once the premise
  spotted".
- **One `harness-sync.toml` per harness folder** — the id already names the harness through its path.

## Revisit if

A user needs files from outside the home directory. Confidence: high.
