# Mask secrets on push and keep each machine's own value on pull

- **Date:** 2026-11-06
- **Governs:** `/`, `harness-sync push`, `harness-sync pull`, `harness-sync secret set`

Git history keeps every secret that a push sends, and a user can push to a public repo. harness-sync replaces each
secret with a secret placeholder on push, and keeps the real value only in the harness files of each machine. The user
enters a rotated secret on each machine.

## Decision

- **Placeholder.** Push replaces each secret value with a named secret placeholder in the remote snapshot. The
  placeholder replaces the whole string value. A string is a placeholder only at the value whose item id it names;
  anywhere else it is plain text, which the scan checks and pull writes as it is.
- **Detection.** A value is a secret when a key on its path matches the name rule, or when the repo's `secrets` list
  names it. A key matches the name rule when, in any case, it is `Authorization`, or ends with `_KEY`, `-KEY`,
  `APIKEY`, `TOKEN`, `SECRET`, `PASSWORD`, or `HEADERS`. The rule is the same for every harness.
- **Scan gate.** Before it commits, push scans the whole outgoing snapshot, whole files included. Push stops when a
  token-like string remains outside a secret placeholder.
- **Pull keeps the machine's own value.** For a secret placeholder, pull keeps the value that the machine already has.
  When the machine has no value, pull asks for it on a TTY. Without a TTY, pull leaves the key out and lists it. A
  missing secret inside an array leaves the whole array out, so that no element of the array moves to another index.
- **Later entry.** `secret set` sets a missing secret from a TTY prompt or from stdin. No command takes a secret value
  as an argument.
- **Missing is not deleted.** A key that pull left out because its secret is missing is not a local deletion on the next
  push: push sends the value of the base commit in its place. The key stops being missing once the local setup holds a
  value at it, so a later deletion of that value is a local deletion.
- **No store.** harness-sync keeps no secret store of its own and puts no encrypted secret into the repo.

## Why

- The brief: no plain-text secret in the repo; masking is the minimum; the user enters the real value on each machine.
- The harness files of each machine already hold the plain value. A second store adds a copy and no protection.
- Name rules miss a secret under an unexpected key, so the scan is a second check.
- pi names provider keys `apiKey` (`models.json`) and kensai-local names them `api-key`; the `_KEY` suffix alone missed
  both (research, 2026-11-07).
- The user: the name rules give as few false positives as possible. A masked value never syncs, and a key that holds a
  secret word before its end, such as `MAX_THINKING_TOKENS` or `apiKeyHelper`, names a setting.

## Consequences

- The user enters a rotated secret on every machine. Accepted.
- A string with secret and non-secret parts, such as an `OTEL_EXPORTER_OTLP_HEADERS` value with several headers, is
  replaced whole. A change to its non-secret part does not sync. Accepted.
- A false positive of the scan blocks the push. How the user marks a value as not secret is not specified.
- A secret under a key that does not match the name rule is found only by the scan or by a declaration in the repo.
  Accepted.

## Rejected

- **Encrypted secrets in the repo** (age or git-crypt: FelixIsaac/claude-code-sync, Cha1000000/claude-code-sync,
  jamie950315/ccsync) — each machine then needs the key, which is a second distribution problem.
- **A secrets file per machine** (Cha1000000/claude-code-sync) — copies values that the harness files already hold.
- **The `${VAR}` expansion of a harness** — needs the variable in the environment of every process that starts the
  harness, and Claude Code does not expand variables in its settings `env` block.
- **Secret keys kept local and never synced** (Hudint/claudesync `localOnlyKeys`) — the key does not reach a new
  machine, so the user does not see which value to enter.
- **Name rules that match a secret word anywhere in a key** (`*TOKEN*`, `*KEY*`) — they mask settings such as
  `CLAUDE_CODE_MAX_OUTPUT_TOKENS` and `apiKeyHelper`, which then never sync.
- **Secret key names built into each harness** — the shared name rule covers the keys of Claude Code and pi.

## Revisit if

Users need a secret to move between machines, for example for frequent token rotation. Confidence: high for one user
with a few machines.

## History

- 2026-11-08 — Missing is not deleted: the key stops being missing once the local setup holds a value at it; the record
  of missing secrets outlived the value, and the deletion of a value set by hand never reached the repo.
- 2026-11-08 — Pull keeps the machine's own value: a missing secret inside an array leaves the whole array out; pull
  removed the element, the later elements moved, and the next push dropped the placeholder from the repo.
- 2026-11-08 — Placeholder: a string is a placeholder only at the value whose item id it names; a token wrapped in
  placeholder-shaped text passed the scan.
