# Sync the Claude Code catalog

- **Date:** 2026-11-07
- **Governs:** `/`, `harness-sync status`, `harness-sync push`, `harness-sync pull`

`~/.claude/` and `~/.claude.json` mix the user-level setup of Claude Code with state, caches, and identity that Claude
Code writes for itself. The Claude Code catalog takes the authored files, the keys of `settings.json`, and a short list
of `~/.claude.json` keys. Five of those keys are undocumented, and harness-sync syncs them on a guess about their
meaning.

## Decision

- **Directories.** The Claude Code harness reads `~/.claude/` and `~/.claude.json`. When `CLAUDE_CONFIG_DIR` is set,
  it reads that directory and the `.claude.json` in it, as Claude Code does.
- **`settings.json`.** Each top-level key is one item. Each entry of `env`, `enabledPlugins`, `extraKnownMarketplaces`,
  `pluginConfigs`, `skillOverrides`, and `modelSettings` is one item.
- **`~/.claude.json` keys.** The items from `~/.claude.json` are: each entry of the top-level `mcpServers`; the keys
  that the settings reference lists with the "Global config" scope; the settings keys that the settings reference says
  fall back to `~/.claude.json`; and the undocumented preference keys `showSpinnerTree`, `diffSidebarOpen`,
  `deepLinkTerminal`, `lspRecommendationDisabled`, and `companionMuted`. No key under `projects` is an item.
- **Files.** Each file of the user instructions (`CLAUDE.md`, `rules/`), `skills/` except `skills/synced/` and
  `skills/.trash/`, `agents/`, `commands/`, `output-styles/`, `workflows/`, `themes/`, and `keybindings.json` is one
  item.
- **Never synced.** Memory, `agent-memory/`, claude-mem data, `pluginPanes`, `companion`, `.credentials.json`, the
  plugin install records and cache ([1.4](/design-docs/adr/1.4-plugin-setup.md)), and the `synced/` directories.

## Why

- `~/.claude.json` had 112 top-level keys on the reference machine on 2026-11-06, and 11 of them were configuration. The
  others were counters, caches, flags, identity, and per-project state.
- On the reference machine, `settings.json` held a secret in `env` and an absolute home path in `statusLine.command`
  next to portable keys (2026-11-04). Key-level items let harness-sync mask or pin these values and move the rest.
- User instructions and settings point to files (`guides/` from `CLAUDE.md`, `statusline.mts` from `statusLine`), which
  sync as referenced files ([1.1](/design-docs/adr/1.1-supported-items.md)).

## Consequences

- How the list of undocumented keys stays current is not specified. Accepted.
- If one of the five undocumented keys is state, harness-sync syncs state. Accepted.

## Rejected

- **Only `mcpServers` from `~/.claude.json`** (tawanorg/claude-sync, aoprisan/ccsync) — misses the Global config keys
  and the fallback keys that `/config` still writes there.
- **Whole-file encryption of `~/.claude.json`** (FelixIsaac/claude-code-sync) — moves the identity, `machineID`, and
  per-project state of one machine onto another.
- **The undocumented `autoUpdates` key** — its effect depends on `installMethod` and `autoUpdatesProtectedForNative`,
  which stay on each machine. On a new machine, Claude Code 2.1.319 rewrote `autoUpdates: false` as
  `env.DISABLE_AUTOUPDATER=1`, which turns off plugin auto-update, and the next push sent that to every machine
  (sandbox, 2026-11-07).

## Revisit if

Claude Code documents a split of configuration and state in `~/.claude.json`. Confidence: medium. Version 2.1.119 moved
`/config` preferences to `settings.json`, and the move can continue.
