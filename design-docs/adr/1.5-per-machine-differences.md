# Handle per-machine differences with pins, a home-path token, and warnings

- **Date:** 2026-11-06
- **Governs:** `/`, `cc-sync init`, `cc-sync push`, `cc-sync pull`
- **Implementation:** pending — pins, the home-path token, and the executable warnings are not built (frame Phase 2)

Machines differ in home directory, OS, shell, and installed software, and a test machine can need values that the other
machines must not receive. cc-sync uses one machine-local mechanism, the pin, for partial sync and for OS-specific
values, and has no layers in the repo. Each machine that needs an override pins it on its own.

## Decision

- **Machine-local state.** Each machine keeps its sync configuration, its base commit, and the local clone of the repo
  in `~/.cc-sync/` (`%USERPROFILE%\.cc-sync\` on Windows). Push never sends them.
- **Pins.** A pinned item keeps its local value, and neither push nor pull moves it. Partial sync and OS-specific values
  both use pins.
- **No layers.** The repo has no OS, host, or profile layers.
- **Home-path token.** Push replaces the home directory prefix of a path in a synced value with a home-path token. Pull
  expands the token to the home directory of the target machine, with forward slashes on Windows.
- **Executables warn.** Pull warns when an executable that a synced command names (status line, hooks, MCP `command`) is
  not on PATH. cc-sync installs nothing; the user manages the executables.

## Why

- The brief: a test machine enables what the remote snapshot disables, and that change must not reach the other
  machines.
- Pins cover partial sync and OS-specific values with one concept.
- Absolute home paths were in 10 places on the reference machine (2026-11-04). The settings `env` block and exec-form
  hooks do not expand `~`, and Git Bash removes backslashes that are not in quotes.
- The user: the management of executables stays with the user.

## Consequences

- Each Windows machine pins its own `statusLine` and hooks. Two Windows machines repeat the same pin. Accepted.
- A pinned item gets no remote change, fixes included. Accepted.

## Rejected

- **OS and host layers in the repo** (Hudint/claudesync `os/<os>.json`, `hosts/<host>.json`) — a second concept for what
  pins cover.
- **File variants per OS** (FelixIsaac/claude-code-sync `name.windows.md`) — a second concept for what pins cover.
- **Installing missing executables** — the user manages the software on each machine.

## Revisit if

Users run several machines per OS that need the same overrides. Confidence: medium.
